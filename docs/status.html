2026-09-19 · Step 1 characterised: WebGL2 repeatable, WebGPU ulp-level variance in every browser; tolerance gate proposed

What was run. The 36-pose × 2 cold-load sequence (qa/pages/repeat.html?sequence=1) in a visible Safari 26.6 window (WebGPU), a visible Brave 153 window, and then in Brave 153 --headless=new with WebGPU over ANGLE Metal, driven through the DevTools protocol so no visible window is needed and nothing throttles. Twenty-one sequences in all (1,512 captures, no capture or save errors): 14 headless WebGPU runs (plain controls, warm=90, stall=300 ms on the first three frames, --disable-gpu-shader-disk-cache, noblob), 5 headless WebGL2 runs, plus the two visible-window runs. Eight cold loads of the ink render target (?scene=inkrt&p=0.64) were hashed separately.

Result. Safari WebGPU: 5/36 pairs differ (so the variance is not a Chromium/Dawn artefact). Headless WebGPU: 22/504 pairs differ (≈4.4%); the rate rose with more concurrent instances. Headless WebGL2: 0/180 pairs differ, bit-identical in every pose and tier. Ink RT: 8/8 identical. Every perturbation (longer warm-up, load stalls, no shader cache, no contact blob) still showed the same intermittent behaviour, so each is excluded as the cause, as are the ink pass and, from Codex's earlier work, MSAA, environment, shadows, derivatives, depth bias, centroid interpolation and every traced CPU upload. The root cause is not demonstrated; the evidence points at a timing-dependent per-load state inside the WebGPU path that shifts shading by an ulp.

Character of a difference (38 saved pairs, metrics in build/step1-pair-metrics-2026-09-19.jsonl from the new qa/frame-compare.mjs): ≤ 1.55% of pixels change; the median ΔE76 of changed pixels is ≤ 0.94 (below the visible threshold); the worst 5×5 block mean ΔE76 is 2.9, and that one is a single star pixel flipping at a glyph edge in a historical T3 pair. Whole-frame cases are 1–3 level scatter where the 1/255 dither flips; relief cases are edge speckle on the lettering. None is a visible change.

Proposal, for the owner's decision — nothing changed yet. Keep bit-exact SHA-256 references for the WebGL2 backend, which is demonstrated repeatable, and for any WebGPU pose that reproduces across cold loads; gate WebGPU frames against blessed PNGs with a tolerance derived from the observed variance (candidate: changed pixels ≤ 1%, median ΔE76 ≤ 1.0, worst 5×5 block ≤ 4.0), so a real regression (moved lettering, changed gold, lighting shift) still fails while ulp scatter passes. This is a change of gate definition, not the acceptance of multiple hash variants. No reference hash changed, no PNG blessed, no gate altered; M7/M8 remain open.
